What is real here, and how does it relate to the BDH paper?

The paper develops a graph view of sparse neurons and synaptic memory. This visualisation is a measured, signed projection of the executable model’s attention memory, not a literal reproduction of the paper’s biological graph. Left-hand nodes are RoPE cue coordinates; right-hand nodes are selected gated neurons. Neither is assigned an invented word or concept.

For one head, the native state is Mt = Σs<t qs ⊗ vs. We display Bt = MtC, where C is the centred gate projection. The complete query-weighted sum of B, divided by the attention LayerNorm standard deviation, reconstructs the gate preactivation. The graph shows memory before the selected token writes. Its edge inspector also reports the post-write value.

Twelve cue coordinates and twelve gate neurons are selected by their peak native activity over this sequence. The 40 displayed connections are selected by peak native memory magnitude; all 144 sampled connections remain in the table. Selection stays fixed during playback and the decay comparison. Omitted coordinates still participate in full inference. Widths share a fixed scale across the sequence and both computed settings.

The checkpoint has no explicit exponential memory decay. In native mode, a smaller projected value can reflect signed cancellation; a smaller query read can reflect changed cues or positional phase. Neither proves semantic forgetting. “Try memory decay” changes the recurrence to Mt+1 = λMt + qt ⊗ vt and reruns the full model, across every head and layer, with unchanged weights. This optional experiment does not alter the baseline instrument or its published results.

Error here is scored on the letter after the selected token. The main instrument aligns error to the target token instead, so compare this panel at t with the main error at t + 1. The final token has no observed successor. The memory norm is the Frobenius norm of the full, unprojected head state; the connection-change counts refer only to the sampled 144 edges.

What this does not show

7 disclosed limitations
  1. Layer 0 shows no effect. This confirms the paper’s own statement about higher layers. Switch the layer control to 0: its phase means show no comparable drop. The shipped run measured 0.92×; we report that as no effect, not as an inversion.
  2. 64× neuron shrink (65,536 → 1,024). This small independent model measures 15.76% in memorize and 5.08% in repeat at layer 2 on the canonical sequence. Absolute rates are specific to this checkpoint and protocol.
  3. Synthetic task only. No claim is made about BDH on natural language. The corpus is a 13-letter warm-up plus a random 8-letter word, by design.
  4. BDH token 0 always reads 0.0%. Attention is tril(diagonal=-1), so token 0 attends to nothing. A code property, not a finding. It is excluded from the warm-up mean on this page: the canonical warm-up mean is 19.65%. The historical 18.14% includes it. The Transformer attends to itself and can have nonzero activity at token 0.
  5. Independent reimplementation. Faithful to pathwaycom/bdh with a measurement hook added and the config shrunk. Not an official BDH model.
  6. One small checkpoint and one synthetic protocol. This experiment does not establish a general law of intelligence, a causal confidence meter, or a result about later BDH-family systems.
  7. Warm-up shows the highest activity, and we cannot say why. On the canonical run, layer 2 averages 19.65% through warm-up (excluding token 0; historically 18.14% including it) against 5.08% on repeats, yet the model’s cross-entropy on the warm-up is 0.113 bits, lower than the 0.766 bits it spends on repeats. These phase means do not support a simple uncertainty explanation. Herrmann et al. also caution that next-token loss alone is a poor proxy for in-context computation complexity. An earlier draft of this note explained the gap as “activity tracks the model’s uncertainty, not the oracle’s.” We measured that and it is false. It is corrected here rather than quietly dropped. One possible explanation is state re-establishment at the start of a cold sequence, and that is untested, and labelled as such. The claim in the bar above is scoped to the memorize → repeat transition precisely because of this gap.

Eight questions, answered plainly.

Is this an official BDH model?

No. It is an independent reimplementation, shrunk for teaching: 1,024 neurons against the paper's 65,536, trained on the synthetic protocol from Section 6.4 rather than on natural language. The architecture follows pathwaycom/bdh with one measurement hook added. No official checkpoint is used, downloaded, or claimed.

Is the computation live, or a recording?

The forward passes are live. Changing the word, the repeat count, or the weight set runs BDH and the ReLU Transformer in your browser on Float32Array buffers. Changing the layer reuses the measurement already computed. Token playback steps through that computed tensor and does not re-run inference for each frame. The fixed offline comparison table is labelled PRECOMPUTED and does not respond to the controls.

Why does layer 0 not show the effect?

We do not fully know, and we report it as a limitation rather than hiding it. All four layers share the same learned tensors, but each one receives a different residual state, transformed by the layers before it. The shipped run measures a 0.92× memorize/repeat ratio at layer 0, which we describe as no effect rather than as an inversion. The paper also locates the behaviour in higher layers.

Why is the warm-up the most active phase?

We cannot say. Layer 2 averages 19.65% through warm-up against 5.08% on repeats, yet cross-entropy on the warm-up is 0.113 bits, lower than the 0.766 bits spent on repeats. That rules out a simple "activity tracks uncertainty" story, which an earlier draft of this page asserted and we then measured and withdrew. State re-establishment at the start of a cold sequence is a plausible explanation and an untested one.

How do you know the browser port is correct?

Both ports are checked against reference tensors dumped from the Python model. BDH parity compares 315,392 raw values per weight set and requires exact active counts and exact zero patterns, not merely close numbers. The Transformer suite additionally mutates the causal mask, the RoPE sign, and the head layout, and fails if the port still agrees. Run node parity_test.js and node transformer_parity_test.js yourself.

Does a lower active count mean it runs faster?

Not here. This page computes densely over the full sequence and measures how many activations are positive. It does not implement a sparse kernel, and it measures no speed, memory, or energy saving. Work on exploiting activation sparsity for inference efficiency is real, but those results belong to that work, not to this demo.

What is the memory graph actually showing?

A measured, signed projection of the model's own attention memory for one head, before the selected token writes into it. Left nodes are RoPE cue coordinates and right nodes are selected gated neurons. They are not the paper's biological synapse graph, not semantic concepts, and not learned weight changes. The decay slider is an explicit intervention that we added: the shipped checkpoint has no decay gate.

Can I reproduce this from scratch?

Yes, and we recorded what happens when you do. Retraining a fresh clone on a different machine produced a 3.37× layer-2 ratio rather than the shipped 3.10×. Training is not bit-identical across platforms, so we publish both numbers instead of quietly reconciling them. The commands are in the repository README.
